# FSL model sourcing and desktop deployment

## Recommended model

Train a custom **MediaPipe Gesture Recognizer** model for the static, one-handed FSL signs in the approved curriculum. Bundle the resulting `.task` file with the Electron installer. Training happens in a pinned Python environment during development. Electron runs inference through `@mediapipe/tasks-vision` in its Chromium renderer, with model and WASM files installed locally. The application can run offline from first launch without a Python installation or a model download. [Google's training notebook](https://github.com/google-ai-edge/mediapipe-samples/blob/main/examples/customization/gesture_recognizer.ipynb) · [MediaPipe Tasks setup](https://developers.google.com/edge/mediapipe/solutions/tasks#model_asset_placement_threading) · [Web Gesture Recognizer](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer?tab=Web)

If the artifact uses pickle, loading it can execute code. Keep serializable `.task` or `.onnx` weights in the desktop installer. ## Training and acceptance

1. Review the taught signs with a Deaf FSL educator. Map stable app sign IDs to the data labels, flag one-hand, two-hand and movement requirements, and identify legitimate variants. Start with static signs with usable coverage. Record the dataset version, terms, approved uses, sign mapping, and attribution. Collect additional data with consenting adult signers and a release covering training and model distribution wherever a class lacks usable examples.
2. Group by signer before creating train, validation and test sets wherever identities are available. Keep frames from one clip or capture session in a single partition. Build a held-out test set of signers and environments absent from training, with left- and right-handed examples, common webcams, varied distance and lighting, and transitions. Track samples dropped when the landmark detector cannot find a hand. Sample a realistic `none` class with hands in resting poses and other off-target gestures that look similar to the supported signs. The webcam path should separately handle frames in which no hand is detected. [Model Maker dataset format](https://developers.google.com/edge/api/mediapipe/python/mediapipe_model_maker/gesture_recognizer/Dataset)
3. Train using the Google notebook in a pinned Python environment, then export with `export_model()`. Save the `.task` bundle alongside reproducibility metadata. Store a small model manifest with version, checksum, stable sign IDs, expected MediaPipe version, supported handedness or input conventions, and threshold settings. Keep training media out of the installer. [Google training notebook](https://github.com/google-ai-edge/mediapipe-samples/blob/main/examples/customization/gesture_recognizer.ipynb) · [Model Maker exporter](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/model_maker/python/vision/gesture_recognizer/gesture_recognizer.py)
4. Calibrate confidence and stable-hold rules on validation clips. Evaluate on the untouched signer split with macro-F1, per-class precision and recall, confusion matrix, false acceptance on `none` and wrong signs, and webcam time from a completed sign to visible feedback. Review mismatches and cue wording with the educator. Establish release thresholds on target classroom hardware before accepting results. Disable auto-scoring for classes that fail, while providing video teaching and manual or visual matching for those signs.
5. If a required sign depends on motion, collect labeled FSL clips and train a separate time-window classifier on timestamped MediaPipe landmarks. Use Hand Landmarker for hand shapes and trajectories. Add both hands and body or face cues only when the taught vocabulary requires those features. Export the temporal model to ONNX for local Chromium inference and evaluate motion confusions independently. A `VIDEO` running mode on its own supplies tracking across frames and still yields framewise gesture decisions. [MediaPipe Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker) · [Gesture Recognizer](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer?tab=Web) · [ONNX Runtime Web](https://onnxruntime.ai/docs/get-started/with-javascript/web.html)

## Packaged inference

- Use an Electron Forge/Packager `extraResource` directory for the `.task`, the pinned Tasks Vision WASM files and loaders, the manifest, and any bundled media. Serve the renderer and those allowlisted assets through the same secure, standard application protocol with fetch support and suitable MIME types. Resolve production resources from `process.resourcesPath`. Configure video streaming and seek support for the lesson clips. [Electron protocol](https://www.electronjs.org/docs/latest/api/protocol) · [Electron Packager extraResource](https://electron.github.io/packager/main/interfaces/Options.html#extraResource)
- Initialize `FilesetResolver.forVisionTasks()` with the local WASM URL and `GestureRecognizer.createFromOptions()` with the local `.task` URL in `VIDEO` mode. Send transferable frames to a worker with monotonic timestamps and at most one in-flight inference. Drop older frames while busy. Compare the best eligible FSL result with the quiz target after confidence and stability checks. Filter out canned labels and train/test the no-match behavior. Keep preview mirroring a presentation choice and use a consistent orientation for model input and evaluation. [MediaPipe Web example](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer?tab=Web) · [Worker guidance](https://developers.google.com/edge/mediapipe/solutions/tasks#model_asset_placement_threading) · [Gesture Recognizer options](https://developers.google.com/edge/api/mediapipe/js/tasks-vision.gesturerecognizeroptions)
- Open camera access only on the webcam activity, for the app's own origin and video media type. Keep camera frames in memory and stop the tracks and worker on leaving the activity or closing the window. If initialization, permission, camera access or hand tracking fails, surface an appropriate status and keep the lesson available. Exercise a clean installed build with network disabled, no Python and no browser cache, including no camera, denied camera, camera unplug, corrupted/missing model and repeated navigation. [Electron session permissions](https://www.electronjs.org/docs/latest/api/session) · [Electron security](https://www.electronjs.org/docs/latest/tutorial/security)

The [training guide](model-training/README.md) records the earlier A/B/C pilot, the 24-letter model and the isolated number and word models. Full-frame classroom webcam evaluation on held-out signers remains open.
